### 1b. What "clean" means, and whether unclean calls still ran

- **Definition.** A clean call is a reply that parses whole as a JSON list holding exactly one `search_corpus` call, with nothing written before or after it (RECORDS R-008 line 370; `scoring.clean_call`).
- **Denominator.** It is counted out of the replies that searched. `clean_call_count` takes the rows with `searched` true and counts how many of those are clean. The two arms therefore have different denominators: the adapter searched in 180 or 184 conversations, base in 136 or 107. In LongMemEval-S the 441/441 count covers every completed question that searched (including questions with no marked evidence), so it is not the same population as the "421 of 466" searched row.
- **Unclean calls still ran.** `harness.search_query` takes the first call that AgentTune's parser finds anywhere in the reply, whether or not text follows it. `run_turn` then runs the search and feeds the result back. So "unclean" means extra text or a second call came with the call. The search still ran, and the turn could still end in a right answer. It is a format measure, not a count of failed searches.
- **Ran out of calls.** This means more than 3 searches in one turn (`MAX_CALLS = 3`).
- **Corollary.** "180 of 180 vs 52 of 136" compares format cleanliness over different denominators. The write-up must say so.

## 4. Does `make_article.py` check or key on record ids in the template?

- **No.** The script only replaces `{{name}}` placeholders and stops on an unfilled one (lines 1941-1953). Its other checks (the `SystemExit` calls) test results files against claims the text makes, for example "no AuditKIT run on 6.37" (line 1501), "seed 82 is lowest" (380, 384) and "a gap near significance" (210). None reads any record id from the template. No test file named for the article exists in tests/ (I did not grep tests' contents). Moving inline ids to "Records:" lines in `docs/article_template.md` and `docs/model_card_template.md` cannot break the script.
- **Ids are hard-coded in the script too.** Generated strings carry them: the `human_check` string (R-144, R-145, lines 1508-1513), the status line (lines 127-130), the ledger rows (lines 1530-1780) and many table captions. Ids moved out of the template will therefore still appear in generated text, or the script must be edited.
- **"Kevin" is also hard-coded.** It is in `out["human_check"]` ("Kevin agreed with the scorer on...") and in ledger strings such as "Kevin's call". The check at line 918 and others use "Kevin" in their messages. Changing "Kevin" to "I" or "the author" in the template alone leaves those strings and rewrites ARTICLE.md and MODEL_CARD.md on the next run.
- **Edit the template, not the output.** Both ARTICLE.md and MODEL_CARD.md are regenerated by the script, so edits to them are lost unless the template (and the script's strings) change.
- **Not generated.** README, ABSTRACT.md, HF_ARTICLE.md, hf_data_card.md and hf_eval_logs_card.md are hand-written, so numbers in them are not cross-checked by the script. I checked the ones below by hand.
